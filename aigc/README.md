## 数据流向：两种核心场景

### 场景一：写日记（引导对话 → 生成日记）

```
用户输入
    ↓
意图识别（规则 80% → LLM 兜底 20%）
    ↓
┌───────────────────────────────────────────────────────────────┐
│  START_DIARY / CONTINUE_DIARY / CONFIRM_GENERATE             │
└───────────────────────────────────────────────────────────────┘
    ↓
对话引擎（主模型）
    ├── L1 短期记忆（最近10轮）
    ├── L2 增量摘要（历史事实压缩）
    └── L3 向量记忆（跨会话检索）
    ↓
用户确认生成 (CONFIRM_GENERATE)
    ↓
日记生成引擎
    ├── 阶段1：事实提取 → 结构化 JSON
    ├── 阶段2：文学润色 → 日记正文 + 心情标签 + 情绪分数
    └── 心情处理 → 查表 / 存为 custom:xxx
    ↓
数据落库
    ├── diaries 表（业务数据）
    ├── vector_store（向量化）
    └── BM25 索引（全文索引）
    ↓
返回前端 → 用户确认 → 完成
```

### 场景二：RAG 问答（检索历史日记）

```
用户提问（如“帮我找开心的回忆”）
    ↓
意图识别 → CHAT / 正常对话
    ↓
RAG 检索引擎
    ├── ① 情绪检索：mood_score >= 7 → 获取日记 ID 列表
    ├── ② 混合检索（在情绪过滤的范围内）
    │      ├── BM25 全文检索 → Top 10
    │      ├── PGVector 向量检索 → Top 10
    │      └── RRF 融合 → Top 3
    └── ③ 构造上下文
    ↓
主模型生成回答（带检索结果）
    ↓
返回前端
```

## 各层核心职责

| 层 | 核心职责 | 关键组件 |
| :--- | :--- | :--- |
| **前端层** | 用户交互、SSE 流式接收、状态管理 | Vue 3, Pinia, EventSource |
| **接入层** | 认证鉴权、路由转发、限流 | JWT, Gateway, Sentinel |
| **业务服务层** | 对话、日记、搜索、用户四大模块 | ChatService, DiaryService, SearchService |
| **意图识别层** | 快速过滤用户意图，降低 LLM 调用成本 | 规则匹配（热更新）+ LLM 兜底 |
| **对话引擎** | 多轮对话管理、三层记忆架构 | L1 Redis + L2 摘要 + L3 PGVector |
| **日记生成引擎** | 事实提取 → 润色 → 心情处理 | 两阶段生成策略 |
| **RAG 检索引擎** | 混合检索（BM25 + 向量 + RRF） | pg_search, PGVector |
| **数据层** | 持久化存储、向量存储、全文索引 | ParadeDB (PG18 + 扩展), Redis |

## 关键技术指标

| 指标 | 数值 | 说明 |
| :--- | :--- | :--- |
| 意图识别规则命中率 | ~80-85% | 关键词匹配，不调用 LLM |
| 意图识别 LLM 兜底调用量 | ~15-20% | 仅规则未命中时调用 |
| 单次对话支撑轮数 | 200+ 轮 | 依赖 L2 增量摘要 |
| Token 成本降低 | 70% | 相比全量对话拼接 |
| RAG 双路召回 Top-3 命中率 | 91% | BM25 + 向量 + RRF |
| 语义检索响应时间 | < 50ms | PGVector HNSW 索引 |
| 全文检索响应时间 | < 30ms | pg_search BM25 索引 |

## 这个架构的面试亮点

| 序号 | 亮点 | 说明 |
| :--- | :--- | :--- |
| 1 | **三层记忆架构** | L1 短期 + L2 摘要 + L3 向量，解决长对话 Token 溢出 |
| 2 | **两阶段日记生成** | 事实提取 + 润色分离，解决 LLM 幻觉问题 |
| 3 | **混合检索** | BM25 + 向量 + RRF 融合，兼顾关键词与语义 |
| 4 | **意图识别分层** | 规则（热更新）+ LLM 兜底，成本与准确率平衡 |
| 5 | **模块解耦** | 聊天模块不依赖日记模块，通过前端 `action` 桥接 |
| 6 | **热更新关键词** | 数据库 + Redis，新增/修改关键词无需重启 |
